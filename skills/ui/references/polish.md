# Polish

Techniques for when a design is structurally sound but feels bland.

## Supercharge defaults

Upgrade elements that already exist instead of adding new ones:

- Bulleted lists → icons (checkmarks, arrows, or content-specific ones like padlocks for security features).
- Testimonial quote marks → oversized, colored, treated as graphic elements.
- Links → weight/color changes, or a thick colorful underline that slightly overlaps the text.
- Form controls → custom checkboxes/radios in a brand color for the checked state. This alone moves a form from browser-default to designed.

## Accent borders

A flat colored bar is zero-skill, high-impact decoration: across a card's top, under a headline, along an alert's edge, marking the active nav item, or spanning the very top of the layout.

## Background decoration

- Change background color per section (or per emphasized panel) to break monotony.
- Gradients work when the two hues are within ~30° of each other.
- Subtle repeating patterns — full-bleed or along one edge — at very low contrast so content stays readable.
- A single geometric shape or simple illustration placed off in a corner. Keep contrast low.

## Empty states are the first impression

Any content-driven feature is first seen empty. Design that state deliberately:

- Add an illustration or image; make the call-to-action the hero.
- Hide supporting chrome (tabs, filters, search) that has nothing to operate on yet.
- A blank table with implicit "no data" is a design failure.

## Use fewer borders

Borders everywhere = cluttered. Before adding one, try:

1. **Box shadow** — outlines without the harshness (best when the element differs from the background color).
2. **Different background colors** — adjacent tints separate content on their own; if both a border and background difference exist, delete the border.
3. **More spacing** — separation via distance introduces no visual noise at all.

## Break component stereotypes

Familiar components don't owe you their default form:

- Dropdowns can have columns, sections, icons, and descriptions — not just stacked links.
- Table columns can merge related fields with internal hierarchy (name over email), embed images, and use color — if a column doesn't need independent sorting, it doesn't need to be a column.
- Important radio groups work better as selectable cards.

## Keep leveling up

Two durable habits: when a design impresses you, hunt for the decision you wouldn't have made yourself (inverted color on a datepicker, a button inside an input, two-tone headlines) — that's where new tools come from. And rebuild interfaces you admire from scratch without inspecting their code; the differences between your version and the original teach the small tricks nothing else will.
